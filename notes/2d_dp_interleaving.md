# 2D DP — 從暴力到優化的思考流程

## 什麼時候用 2D DP
- 有兩個獨立的變量（例如兩個字串各自的 index）
- 暴力 DFS 會有指數級複雜度，但「不同的狀態數」其實很少（m*n）
- 常見題型：兩個字串比對、路徑問題、子序列問題

## 思考流程（用 97. Interleaving String 為例）

### Step 1：先想暴力解
每一步有兩個選擇（從 s1 拿或 s2 拿）→ DFS → O(2^(m+n)) 太慢

### Step 2：找出「狀態」
問自己：什麼資訊能完整描述當前位置？
→ `(i, j)` = s1 用了 i 個字元、s2 用了 j 個字元
→ s3 的位置不用額外追蹤，因為 `s3[i+j]` 就是當前要配對的

### Step 3：算狀態數量
i 有 m+1 種、j 有 n+1 種 → 只有 O(m*n) 個不同狀態
→ 用 DP table 記住每個狀態的結果，避免重複計算

### Step 4：定義 dp
**`dp[i][j]` = s1 的前 i 個字元和 s2 的前 j 個字元，能不能交錯組成 s3 的前 i+j 個字元**

定義要完整：不只說「走到哪裡」，要說清楚「代表什麼的什麼（True/False）」。

### Step 5：Base case
```
dp[0][0] = True                                    # 都取 0 個 → 空字串 match 空字串
dp[i][0] = dp[i-1][0] and s1[i-1] == s3[i-1]      # 只用 s1
dp[0][j] = dp[0][j-1] and s2[j-1] == s3[j-1]      # 只用 s2
```

注意：邊界**不是全部 False**。只用 s1（或只用 s2）是有可能 match s3 的。
注意：只需要比一個字元 `s1[i-1] == s3[i-1]`，不用比整段 `s1[:i] == s3[:i]`（O(1) vs O(i)）。

### Step 6：轉移方程
```
dp[i][j] = (dp[i-1][j] and s1[i-1] == s3[i+j-1])    # 最後一個字元由 s1 提供
         or (dp[i][j-1] and s2[j-1] == s3[i+j-1])    # 最後一個字元由 s2 提供
```

### Step 7：Space 優化
轉移只看「上一行同位置」和「當前行左邊」→ 只需要一維陣列 O(n)

```python
dp = [False] * (n + 1)
# 填好第 0 行（只用 s2 的邊界）
for i in range(1, m + 1):
    tmp = [False] * (n + 1)
    tmp[0] = dp[0] and s1[i-1] == s3[i-1]
    for j in range(1, n + 1):
        tmp[j] = (dp[j] and s1[i-1] == s3[i+j-1]) or (tmp[j-1] and s2[j-1] == s3[i+j-1])
    dp = tmp
```

## 複習時問自己

### 1. 怎麼從暴力解想到 DP？
找出「狀態」→ 數狀態數量 → 如果遠少於暴力的分支數，就用 DP 記住結果。

### 2. dp[i][j] 的定義要包含什麼？
不能只說「走到 (i,j)」。要說完整：「s1 前 i 個和 s2 前 j 個能不能組成 s3 前 i+j 個」。

### 3. 邊界為什麼不是全 False？
`dp[i][0]` 代表只用 s1，如果 s1 的前綴剛好等於 s3 的前綴，就是 True。

### 4. 為什麼邊界比較只需要一個字元？
`dp[i-1][0]` 已經保證前面都 match 了，只需要檢查新增的 `s1[i-1] == s3[i-1]`。

### 5. Space 優化的條件是什麼？
轉移只依賴「上一行」和「當前行已填的部分」→ 可以用滾動陣列壓到一維。

## 適用題目

| 題目 | 狀態定義 |
|------|----------|
| 97. Interleaving String | dp[i][j] = s1[:i] 和 s2[:j] 能否交錯成 s3[:i+j] |
| 72. Edit Distance | dp[i][j] = s1[:i] 轉成 s2[:j] 的最少操作數 |
| 1143. Longest Common Subsequence | dp[i][j] = s1[:i] 和 s2[:j] 的 LCS 長度 |
| 115. Distinct Subsequences | dp[i][j] = s1[:i] 中有幾種方式選出 s2[:j] |
| 62/63. Unique Paths | dp[i][j] = 到達 (i,j) 的路徑數 |
| 64. Minimum Path Sum | dp[i][j] = 從 (0,0) 到 (i,j) 所有路徑中總和的最小值 |

## 1D 滾動陣列優化（Rolling Array）

當轉移只依賴「上一行」和「當前行左側已填的值」，可以把 `dp[m][n]` 壓成 `dp[n]`，space 從 O(m*n) → O(n)。

### 關鍵：掃描順序決定新舊語意

用 `dp[j]` 掃過當前行時（**左到右**）：

| 值 | 讀到時的語意 |
|----|-------------|
| `dp[j]`（還沒被這一輪覆寫） | = `dp[i-1][j]` = 上一行同欄 = **從上面來** |
| `dp[j-1]`（已被這一輪覆寫） | = `dp[i][j-1]` = 當前行前一欄 = **從左邊來** |

```python
# 64. Minimum Path Sum 的 1D 版本
dp = [0] * n
dp[0] = grid[0][0]
for j in range(1, n):
    dp[j] = dp[j-1] + grid[0][j]          # 第 0 行
for i in range(1, m):
    dp[0] += grid[i][0]                    # 第 0 列
    for j in range(1, n):
        dp[j] = min(dp[j], dp[j-1]) + grid[i][j]
return dp[-1]
```

### 什麼時候必須左到右？什麼時候必須右到左？

- **左到右**（這題）：轉移需要「左邊的新值」（當前行已更新）
- **右到左**（0/1 Knapsack）：轉移需要「左邊的舊值」（上一輪未更新），所以要反向掃才不會先覆寫掉需要的資料

面試官常問「為什麼是這個掃描方向？」— 要答得出來。

### 何時 1D 優化會失效

- 需要回溯實際路徑 → 必須留完整 2D 表
- 轉移依賴多於 2 行（例如 dp[i-2] 也要）→ 需要保留更多行
- 轉移跨越整個 row（不只左鄰）→ 覆寫會破壞資料

## 64 與 97 的對比

| 面向 | 97 Interleaving | 64 Min Path Sum |
|------|----------------|-----------------|
| 狀態語意 | Boolean（能否組成） | 數值（最小和） |
| Base case | 邊界要一個字元一個字元比對 | 邊界是前綴累加 |
| 轉移 | `OR` 兩個選擇 | `MIN` + 當前值 |
| 難點 | 狀態定義完整性、邊界不是全 False | 記得加 `grid[i][j]`、單陣列掃描方向 |

**共通 takeaway**：dp 定義要完整說出「兩個變量意義 + 回傳值意義」，不能只說「走到哪裡」。
